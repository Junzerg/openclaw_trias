# 产品需求文档 (PRD)：OpenClaw 「赛博三权分立」可视化多智能体系统

**文档版本**：V 1.0
**产品基调**：极客浪漫、政治模拟、可视化工作流、像素风 (Pixel Art)
**底层驱动**：OpenClaw / Python (`import antigravity`)

## 1. 产品概述 (Product Overview)

### 1.1 项目背景

近期，基于开源 AI Agent 框架 **OpenClaw** 的“三省六部制”多智能体架构在社区爆火。传统的集权式/层级式工作流在执行确定性任务时效率极高，但在面对复杂、发散性需求时，单体/单线 Agent 容易出现“幻觉”闭环，且高权限工具的调用缺乏旁路监督。

为此，本项目提出构建一个基于**“三权分立”（立法、行政、司法）**的全新 OpenClaw 变体。通过引入 Agent 之间的制衡、辩论与审查机制来提升任务容错率，并配以**像素风动态演播厅**，将枯燥的 LLM 思考日志转化为极具观赏性的“赛博政局”与“电子盆栽”。

### 1.2 核心目标

1. **多视角辩论（防幻觉）**：通过议会激辩达成共识，生成最优执行法案（SOP）。
2. **绝对安全合规（防越权）**：利用司法审查机制，对 OpenClaw 底层工具的高危调用进行物理熔断。
3. **高观赏性监控（可视化）**：将后台的 Token 消耗、状态流转映射为生动的 8-bit 像素动画（提案、吵架、敲法槌）。

---

## 2. 核心系统架构：赛博三权分立

系统将 OpenClaw 的各类 Agent 和 Skill 划分为三个相互独立、相互制衡的权力分支：

### 2.1 🏛️ 立法分支 (Legislative Branch) —— “方案规划与辩论”

- **职责**：接收用户（扮演选民/造物主）的原始需求，将其拆解为技术方案草案（法案）。
- **角色组成**：
  - **议长 Agent**：控制流程节奏，发起表决。
  - **激进派议员 Agent**：追求效率，偏好使用最新工具，方案通常大胆激进。
  - **保守派议员 Agent**：注重边界条件、安全异常处理，专门给激进派“找茬”。
- **核心机制【议会辩论】**：方案必须经过两派的互相 Critique（互评）。达成共识并投票通过后，生成正式的《执行法案》（JSON 格式的工作流描述）。

### 2.2 🏢 行政分支 (Executive Branch) —— “调用工具与干活”

- **职责**：拿到议会通过的《执行法案》后，负责实际调用 OpenClaw 的底层 Skills（如 `CodeExecution`, `FileOperations`, `WebSearch`）完成任务。没有规划权，只有执行权。
- **角色组成**：总统 Agent（统筹分发）、内阁部长 Agent（具体干活的职能节点）。
- **核心机制【行政否决 Veto】**：若总统评估当前 Token 预算不足，或发现法案在技术上无法调用对应的 Skill，可行使否决权，将法案打回议会重构。

### 2.3 ⚖️ 司法分支 (Judicial Branch) —— “合规审查与安全沙箱”

- **职责**：充当系统的安全护栏（Guardrails）与最终 QA 验收。
- **角色组成**：首席大法官 Agent。
- **核心机制【违宪审查】**：旁路监听行政分支的动作。若发现代码包含死循环、尝试执行危险系统命令（如 `rm -rf`），或最终产出完全偏离了用户最初的需求，大法官将立刻敲下法槌判定“违宪”，强制物理熔断并打回重做。

## 3. 动态像素场景设计 (Pixel Art Visuals) ⭐️核心高光

前端通过 WebSocket 实时解析 OpenClaw 后端 Agent 的通信日志流，驱动 2D 像素引擎（如 Phaser.js / React-Canvas），实现行为高度可视化。

### 3.1 场景一：议会大厅 (The Parliament)

- **视觉布局**：左右对立的阶梯状议席，中央为演讲台。
- **【提案环节】**：
  - 代表用户 prompt 的信使将信件送入大厅。
  - 议员小人走上【演讲台】，展开卷轴，头顶冒出气泡（打字机效果显示方案拆解步骤）。
- **【名场面：议员吵架】**：当激进派与保守派 Agent 产生逻辑分歧，进入对齐阶段时触发。
  - **Lv1 正常辩论**：座位上的小人交替冒出文字气泡（如：“这会导致内存泄漏！”）。
  - **Lv2 激烈冲突**：当争议度（Conflict Score）飙升，两拨小人脸部变红，离开议席互相靠近。**画面中开始跨党派互扔像素纸团、皮鞋、咖啡杯（带抛物线物理特效）**，气泡爆出 `🤬`、`💢`。
  - **Lv3 议长控场**：屏幕微震，议长疯狂敲击法槌，伴随 8-bit `咚咚咚` 音效和巨大 `ORDER!` 飘字，强制双方冷静。

### 3.2 场景二：行政格子间 (The Oval Office & Bureaucracy)

- **视觉表现**：横向卷轴的总统办公室与下属格子间。
- **动态交互**：法案通过后，总统拿起羽毛笔签字，触发绿色 `APPROVED` 盖章特效。随后，格子间里的“部长”小人们开始疯狂敲击键盘，屏幕闪烁代码流（代表 OpenClaw 正在调用 Skill 执行耗时操作）。报错时小人头上会冒黑烟。

### 3.3 场景三：最高法院 (The Supreme Court)

- **视觉表现**：全黑背景，聚光灯打在高高在上的像素大法官身上。
- **动态交互**：任务交付前进入审查期。
  - **合宪通过**：法官高举法槌落下，闪烁绿光，浮现 `CONSTITUTIONAL`，任务成果打包发给用户。
  - **违宪驳回**：屏幕剧烈震动，红光警报。法槌重砸，甩出红色 `UNCONSTITUTIONAL` 印章，法案卷轴碎裂燃烧，强制退回议会。

## 4. 数据字典与事件流 (WebSocket Event Mapping)

为实现后端逻辑与前端渲染的解耦，定义统一的 JSON 事件推送流：

| 触发阶段 | OpenClaw 后端状态       | WebSocket 推送指令 (示例)                  | 前端像素动画响应             |
| :------- | :---------------------- | :----------------------------------------- | :--------------------------- |
| **立法** | Agent 生成初版草案      | `{"action": "propose", "text": "提议..."}` | 议员上台，展开卷轴           |
| **立法** | Agent 提出强烈反对意见  | `{"action": "throw_shoe", "intensity": 9}` | 触发高烈度扔鞋/扔纸团动画    |
| **立法** | Agent 达成共识生成 SOP  | `{"action": "vote_passed"}`                | 议长敲槌，全场亮绿灯         |
| **行政** | 调用底层 Tools 执行     | `{"action": "executing_tool"}`             | 总统盖章，部长敲键盘/冒汗    |
| **司法** | 触发安全护栏/结果不达标 | `{"action": "unconstitutional"}`           | 法官宣判，红屏震动，物理熔断 |

## 5. 终极实施路线：The Antigravity Magic

本项目的开发将发扬 Python 极客精神：用最少、最优雅的代码，实现最酷炫的“起飞”效果。

- **Phase 1: 后端权力拆分**
  - 基于 OpenClaw 构建 Legislator, Executive, Judge 的 Persona 和权限隔离状态机。
- **Phase 2: 通信总线桥接**
  - 搭建 FastAPI + WebSocket 服务，将大模型自然语言输出及思考日志（CoT）解析为结构化 UI 动作指令。
- **Phase 3: 像素演播厅实装**
  - 引入 Phaser.js 实现前端，绘制/搜集 Sprite Sheets（议员吵架、扔皮鞋、法槌落下等帧动画）。
- **Phase 4: 终极飞行 (`import antigravity`)**
  - 利用 Python 的模块化优势，编写极简启动脚本。
  - 最后，我们将致敬 Python 经典的漫画彩蛋：当用户在终端部署完所有环境，只需在入口文件 `main.py` 写下以下代码。随着程序的运行，赛博议会将在零重力下完美运转，自动打开浏览器，为您呈现一场精彩绝伦的 AI 政治博弈。

```python
from openclaw_trias import CyberParliament

# 启动三权分立与像素可视化引擎，让系统一键起飞
import antigravity

if __name__ == "__main__":
    CyberParliament.launch(port=8080)
```
