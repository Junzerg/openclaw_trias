# Phase 3 Task 3-C: 🏛️议会大厅场景与吵架系统

## 任务目标
实现立法分支的可视化，通过 WebSocket 事件动态渲染议员从文明辩论到全武行的冲突表现。

## 前置依赖
- [Task 3-A](task3.1_frontend_scaffold.md) 完成 WebSocket 客户端和 Phaser 环境建立。
- [Task 3-B](task3.2_art_assets.md) 初步人物与大厅环境图集可用。

## 具体执行步骤
1. **静态场景布局**
   - 实现 `ParliamentScene` 继承 Phaser.Scene。加载议会大厅背景。
   - 左右对立部署**红方 (保守党)**与**蓝方 (激进党)**角色，以及上方中央的**议长**。
2. **文本气泡冒字动画 (`propose` / `debate`)**
   - 捕捉 WebSocket 传来的 `propose` 动作：激进派或保守派头上浮现像素聊天框。
   - 实现 **Typewriter (打字机效果)**，将 JSON `text` 字段逐字显示在画布正中上方的面板中或角色头顶。
3. **分歧冲突系统 (Lv1 ~ Lv3)**
   - 监听系统带来的 `brawl` / `intensity` 参数，渲染怒气值攀升的表现：
     - **轻微分歧 (Intensity < 5)**：快速的嘴炮互相攻击，不需要扔东西，仅语速变快、对话叠化。
     - **肢体冲突 (Intensity > 5)**：调用 Phaser 内置 Arcade Physics。议员变红包围滤镜 (`setTint`)。实例化咖啡杯、皮鞋等武器，从一侧以抛物线扔向对面。添加碰撞检测和消失动画。
     - **议长控场 (`order`)**：`camera.shake()` 主摄镜头震波，极大字体 `ORDER!` 覆盖中央区，伴随物理法槌的猛烈敲击点特效。
4. **通过机制 (`vote_passed`)**
   - 全体亮绿光，议长盖下大章印。页面滑向/过渡到下一个行政执行场景。

## 验收标准
- [x] 后端触发 `POST /petition` 导致议员争辩时，网页前端角色能及时输出相应的辩论片段文本气泡。
- [x] 分歧超过阈值前端能触发扔皮鞋或者飞咖啡杯抛射线。
- [x] 议长介入能引起屏幕震动。
