# Phase 5 - Task 5-A: 基础交互舱 (输入与交付 UI)

> **前置依赖**: Phase 3 场景系统完毕
> **包含项**: 5.2.1, 5.2.2, 5.3.1, 5.3.2
> **模块特性**: 前端业务组件 / 状态绑定

## 📌 目标
本任务旨在构建 OpenClaw-Republic 的前端业务入口与出口。用户将通过此模块提交提案（Petition），并在任务流转期间查看大盘进度，在任务执行完毕后查看最终的交互产物（总统签署的备忘录或最高法院的违宪判决书）。该任务主要关注常规 DOM 卡片渲染与数据的双向绑定，不涉及复杂统计图表的绘制。

## 📋 涵盖子项
- **5.2.1 Prompt 输入面板**: 用户提交需求，支持多行文本、快捷模板载入。
- **5.2.2 任务状态卡片**: 实时展示法案生命周期状态 + 当前激活场景指示（DRAFTING / DEBATING / EXECUTIVE...）。
- **5.3.1 总统交付备忘录**: 任务顺利完成后的成果面板：代码/文件/文本输出渲染。
- **5.3.2 判决书展示**: 司法审查触发驳回时的结果详情：合宪理由 / 违宪理由 + 导致失败的 Traceback 信息。

## 🛠️ 实现建议
- 在前端场景组件外层创建 `components/ui` 或 `scenes/ui_overlay` 的 React 罩层目录。
- **输入面板**: 设计一个美观的赛博风格悬浮输入框。
- **状态卡片**: 位于屏幕上方或边角，结合 React State 实时反应后端的进程节点流转。
- **结果面板**: 在收到 `constitutional` 判决或最终任务闭环事件后，弹出覆盖全屏或居中的暗色半透明 Delivery 面板展示结果详情，支持 Markdown 富文本渲染。

## 验收标准
- [ ] 界面上新增直观的“提交议案”入口，且至少内置两套快捷请愿模板。
- [ ] 顶部或侧边栏新增“状态卡片”，随 WebSockets 游戏状态进行动态 UI 更新。
- [ ] 系统流程完结（不论成败）时能自动弹出格式清晰的“交付备忘录”或“法庭判决书”弹窗。
- [ ] 所有新加 DOM 组件均切合 8-bit / 赛博朋克的科技视觉风格。
