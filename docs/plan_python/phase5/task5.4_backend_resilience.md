# Phase 5 - Task 5-D: 业务规则防线 (LLM 与循环熔断)

> **前置依赖**: 后端 Phase 2 状态机完成
> **包含项**: 5.6.1, 5.6.2, 5.6.3, 5.6.4
> **模块特性**: 后端保障体系 / 容错机制 / 死循环斩断

## 📌 目标
作为独立防线专治后端隐疾。多智能体系统在实弹运转时极易遭遇“网络请求超时限流”、“无限互相反驳死循环”、“总统与议会无限扯皮(Veto回旋)”等崩溃场景。本工程就是主控状态机的保护伞和断路器。

## 📋 涵盖子项
- **5.6.1 LLM 超时与外部限流**: 在框架的最底层 API (调用 GPT 等处)，加入 HTTP 级异常捕获，并实装指数退避重试 (Exponential Backoff)。
- **5.6.2 Skill 执行失败**: 在“行政部委”执行外挂脚本出错（语法错、包缺失）时，不让整个引擎立刻挂掉退出，而是将“错误对象”打包发还为系统内信息，引发重试或 Veto 退回。
- **5.6.3 Veto 重入循环**: 建立对单一法案退回票数的计数器，达到上限后系统将强制中止并判定请愿失败。
- **5.6.4 违宪重做上限**: 司法分支打回重审次数若达极值，系统抛出特别熔断态。

## 🛠️ 实现建议
- 引入并配置 `tenacity`（Python 出色的重试容错工具）来包裹 LLM 和 Web 请求。
- 在状态共享内存或 `State` 基类中，新增防抖标识：如 `veto_count`、`revision_count`。
- 在流程编排（Graph Runtime / Task Logic）的核心 `invoke()` 前注入 Interceptor：如果察觉计数达标，将状态引导至特殊的 `ABORTED` 或 `MANUAL_REVIEW` 尾节点。

## 验收标准
- [ ] 后端关闭网络代理引发 400 失败时，底层能够稳定地打平记录、指数退避、并不停向前端通告 “正在为您拉起自动重试中…” 直至超时。
- [ ] 构造一个极端顽固的对立议题交由左右派对冲，成功触发最大回合数并跳出。
- [ ] 在工具调用（Tool_Call）层面强行植入一段必定发生语法 Error 的代码，证明引擎能咽下异常并继续完成判定，未触发系统级 Panic。
