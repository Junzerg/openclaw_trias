# Phase 5 - Task 5-E: 通信韧性底座 (WS 断线重连)

> **前置依赖**: 前后端 Phase 2 基础 WebSocket 已联通
> **包含项**: 5.6.5
> **模块特性**: 全栈基础架构 / 自愈网络层

## 📌 目标
强化前沿阵地的网络心跳和断连补充机制。项目对 WebSocket 极其依赖，前端画面全是后端吐出的帧指令。若发生短暂网络波动，画面将永久挂滞。我们要编写一套坚韧的网络自愈层应对此类事故。

## 📋 涵盖子项
- **5.6.5 WebSocket 断线重连**: 
  - 前端：检测异常断连、按固定阈值重连拉起、断流期间用户层提示。
  - 后端：连接保活（Ping-Pong）、Session 游标暂存与历史事件重发机制。

## 🛠️ 实现建议
- **前端重连改造**: 将目前裸写的 WebSocket 客户端替换封装，引入心跳包下发机制；当检测出 `onclose (code != 1000)` 时触发自动轮询重连，并在 UI 层面遮罩提示《信号中断 - 正在回拨 1/5》。
- **后端缓存队列**: 引入以 `Task_id` 或 `Session_id` 为 Key 的缓存事件列阵。前端重连时可以指派最近拿到的 `event_head_id`，后端在此基础计算 Diff 并一股流把空窗期所有事件发下以拉齐状态。

## 验收标准
- [ ] 服务器主动中断进程（或强制重启应用），前端立现报警，并在服务器恢复后无缝续连接轨（模拟宕机恢复）。
- [ ] 拔掉前端网线 10 秒发生重连尝试倒计时，插回网线后不但立刻连上，还要补发遗漏的动画动作。
- [ ] 整个重连逻辑能够保持良好的封装，对正在运行的组件场景代码无需侵入式变动。
