# Phase 5 - Task 5-C: 可视化遥测大屏 (图表组件)

> **前置依赖**: Phase 3 及 4-A
> **包含项**: 5.5.1, 5.5.2, 5.5.3, 5.2.3
> **模块特性**: 前端数据可视化 / 统计度量

## 📌 目标
专门处理系统实时的定量数据展示问题（即 Metrics 可视化）。将系统中抽象的资源消耗量（Money Token与Time Cost）、以及群体社会的情绪值（Conflict Score）进行高质量制图。与文本 UI 彻底解耦，独立开发。

## 📋 涵盖子项
- **5.2.3 Conflict Score 仪表**: 实时渲染议会辩论分歧值高低起伏的走势图。
- **5.5.1 实时 Token 消耗**: 细分展现立法/行政/司法三权架构中，到底是谁消耗了最多的算力成本，通过动态饼图或环形图呈现。
- **5.5.2 辩论轮次计数**: 当前议案正处于第 N 轮博弈的数据卡。
- **5.5.3 执行耗时指标**: 每一步后端 Skill 调度引擎调用的耗时瀑布流分析图。

## 🛠️ 实现建议
- 引入企业级图表库 (如 `Recharts`、`ECharts-for-React`)。为了贴合 8-bit 或像素极客风底色，务必设计一套符合 Cyberpunk (荧光绿/霓虹粉/冷蓝调) 的深色系专属 Theme。
- **Conflict Score 折线图**: X轴按事件/轮次递推，Y轴映射分歧绝对值，提供极值红线预警标尺。
- **Token 消耗**: 以环形图呈现总计数据，Hover 显示确切金额。
- **耗时图**: 利用横向条形图展现各组件在单次任务中的执行时间长短比例，暴露系统的阻塞短板。

## 验收标准
- [ ] 成功集成选型良好的 React 绘图库，完成无违和感的赛博主题定制。
- [ ] 随着后端 WebSocket 实时回传的 `intensity` 与 `token_usage` 数据，图表组件能够顺滑更新而无需全局刷新。
- [ ] 添加性能排查用的组件耗时直方图/瀑布图。
