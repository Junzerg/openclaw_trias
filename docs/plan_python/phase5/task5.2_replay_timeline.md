# Phase 5 - Task 5-B: 深度追踪流 (回放与日志系统)

> **前置依赖**: Phase 3 及 4-A 基本外壳
> **包含项**: 5.5.1, 5.5.3
> **模块特性**: 前端 Markdown 日志流 / 超长文本渲染优化

## 📌 目标
本任务聚焦于前端的长文本与时间线组件渲染。后端 Agent 系统产生的复杂思维树 (CoT) 及各分支活动事件，需要以直观、可追溯的双线折叠面板展示给广大观察者，从而彻底打破大语言模型在推理事物时的黑盒属性。

## 📋 涵盖子项
- **5.5.1 辩论时间线**: 可点击展开查看议会上每一轮 Critique/Rebuttal 背后详细 CoT 日志和打分意图。
- **5.5.3 分支活动日志**: 按立法、行政、司法分组展现系统事件流、引擎警告、与调试级日志的时间线记录。

## 🛠️ 实现建议
- 设计一个可折叠隐藏的长侧边栏或位于下半屏的 Drawer 抽屉面板，用于承接大量推流文本。
- **辩论时间线**: 将每轮发言解析为 `[Time] [Role - Stance]: message` 的 UI 结构，主内容只显示梗概，并提供“展开 CoT 详情”的手风琴功能。
- **分支活动日志**: 给日志添加 Tag Filter（议会/总统府/最高法），用强对比度的不同颜色对标签进行视觉切分。
- **重要渲染优化**: 为了防止多轮辩论的海量长文本涌入导致 DOM 节点爆炸致使动画卡顿，建议对日志区域引入 `react-window` 等虚拟列表渲染库，或设定最高保留 200 条的回滚机制。

## 验收标准
- [ ] 成功渲染活动日志面板，各分支的事件可用 Tag 快速过滤。
- [ ] 议员们在辩论时产生的隐式长篇 CoT 内容能够被折叠收集，并可通过鼠标点击流畅展开。
- [ ] 经历一小时的高强度推流演练，日志面板也不会造成严重的内存泄漏与 React 卡顿。
