# Phase 5 - Task 5-G: 最终防线战 (端到端基准测试)

> **前置依赖**: 必须在 4-A 至 4-F 均合并收敛后进行
> **包含项**: 5.1.1, 5.1.2, 5.1.3
> **模块特性**: 综合 QA / 不产生业务新特性

## 📌 目标
在完成所有新组件与防崩溃垫板后，这是 Phase 5 的休止符。纯进行全盘扫除、极端全链路自动化走查验证和压力性能报告计算。本阶段是上线（迈向极简演示态）前最后的封版关卡。

## 📋 涵盖子项
- **5.1.1 全链路冒烟测试**: 将一贯最常演练的一套请愿剧本打到底（请愿 -> 法令设计 -> 两院辩论 -> 总统画押 -> 本地执行 -> 司法首肯）。
- **5.1.2 异常路径验证**: 专挑有毛病的路线，定向诱变触发【司法回炉】与【总统否决】后系统能否不罢工接着跑第二趟。
- **5.1.3 性能基准测试与收尾收集**: 整理耗时，生成标准基准统计（包含系统完成特定议程的预期 API 成本统计、前台帧数开销检测等）。

## 🛠️ 实现建议
- 后端建议使用 `pytest` 配置模拟前台操作，串联起包含真实外部请求的庞大集成跑道。也可以配合脚本做一键打桩，不至于每验证一次等十分钟。
- 人工开启 Chrome 的 Performance 监测以及各类内存监视，留档取样出报告资料。
- **录屏与产卷**: 对着这套集成了 UI 与大数据的终极系统，执行高质量的全程实况录像，将作为展示的核心交付物。
